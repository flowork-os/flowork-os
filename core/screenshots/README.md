## 1. Executive Role

`/opt/floworkos/screenshots/` is the unified visual capture vault for **Flowork OS**. It centralizes desktop screen captures, Ambient Eye visual telemetry, interactive snipping outputs, and WebP thumbnails indexed into **FlowFS Multimodal Screen Memory** for semantic recall across sessions and users.

### Non-Dualism & Capture Path Policy
- **System-Wide Ambient Vault (`/opt/floworkos/screenshots/`):** Default destination for global Ambient Eye (`flowork-ambient-eye`), CLI capture utilities (`flowork-screenshot`), and cross-user system diagnostics. Configured with world-writable permissions (`0777`) so desktop sessions work across multi-user accounts and Live ISO boots without hardcoded user paths.
- **User Agent Capture Path (`$HOME/Pictures/Screenshots/`):** Default destination for the agent-invoked `take_screenshot` tool (resolved via `AppPaths.user_screenshots_dir` in `mrflow-rs/src/config/mod.rs`), with optional `/dev/shm` RAM-only mode for high-frequency inspection.

## 3. Capture Subsystems & Invocation Pipelines

### A. Global Ambient Eye (`/opt/floworkos/bin/flowork-ambient-eye`)
Triggered globally via desktop hotkey **`Super + Shift + A`** (or directly from shell):
1. Captures root display (`$DISPLAY`, fallback `:0`) via `maim` (with fallback to `import -window root` or `scrot`) to `/opt/floworkos/screenshots/ambient_<timestamp>.png`.
2. Updates runtime `ambient_latest.png` and copies the PNG image directly into the X11 clipboard (`xclip`) for instant `Ctrl+V` paste into Mr. Flow.
3. Queries active window title (`xdotool getactivewindow` / `getwindowname`) and display dimensions (`xdpyinfo`), writing `ambient_latest.json`.
4. Indexes the frame into **FlowFS Multimodal Screen Memory** (`flowfs_core.index_screen_capture`), generating a `320x180` WebP thumbnail under `/opt/floworkos/screenshots/thumbs/<basename>_thumb.webp` and storing vector embeddings in `~/.local/share/flowork/flowfs.vec.db`.
5. Publishes an `ambient.captured` event onto the **Cross-App Neural Bus** (`/opt/floworkos/bin/flowork-bus`), triggers an acoustic shutter sound (`/opt/floworkos/bin/flowork-sound-forge`), and shows a desktop HUD toast.

### B. Unified Screenshot CLI (`/opt/floworkos/bin/flowork-screenshot`)
Detached XFCE/X11 CLI capture tool (`FLOWORK_SCREENSHOT_DIR` overrides default `/opt/floworkos/screenshots`):
- **Fullscreen:** `flowork-screenshot` (or `PrintScreen` keybinding).
- **Area / Snippet:** `flowork-screenshot --area` / `--snippet` (uses `maim -s`).
- **Active Window:** `flowork-screenshot --window` (`maim -i <active_window_id>`).
- **Explicit File:** `flowork-screenshot /tmp/verify.png` (or `--file <path>`).

### C. Autonomous Agent Tool (`take_screenshot`)
Defined at `/opt/floworkos/tools/take_screenshot/` (`manifest.json`, `run.py`):
- Streams `maim` directly through memory (`Pillow`), avoiding intermediate scratch files.
- Supports `target` (`"full"` | `"active"`), `compress` (downscales to `1600x1000` LANCZOS or `1280x720` BILINEAR when `fast: true`), and `ram_only` (writes to `/dev/shm/flowork_framebuffer.{png,webp}`).
- Broadcasts screenshot availability to active Mr. Flow Companion Sidebar sockets (`/tmp/mrflow-sidebar-*.sock`).

### D. Native Kernel / Daemon DRM Capture (`flowork-sysd`)
`/usr/local/bin/flowork-sysd` (`http://127.0.0.1:18090`, `sysd/src/drm_capture.rs`) exposes `POST /api/system/display/capture`, `GET /api/system/display/drm`, `POST /api/agent/app/capture`, and `POST /api/agent/browser/capture` for low-level framebuffer and headless CDP captures.

## 4. FlowFS Screen Memory Retrieval

Indexed captures in `/opt/floworkos/screenshots/` are searchable semantically via `/opt/floworkos/bin/flowfs-search`:

```bash
# Search captured screen contexts by window title, app class, or extracted text
/opt/floworkos/bin/flowfs-search --screen "DesignCraft" --json
```
