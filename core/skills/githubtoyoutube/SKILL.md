# GitHub To YouTube (`githubtoyoutube`)

## 1. Objective
Equip Mr. Flow and Flowork OS agents with an end-to-end autonomous pipeline to transform open-source GitHub repositories into viral, broadcast-grade vertical YouTube Shorts (9:16, 1080x1920, 55–60s) and long-form visual documentaries with 100% English voiceover, non-overflow safe frame margins, prominent GitHub URLs, and automated viral SEO keyword research.

## 2. Prerequisites
1. **Graphics & Audio Utilities:** FFmpeg with NVENC hardware acceleration (`h264_nvenc`), PyCairo (`python3-cairo`), and `edge-tts`.
2. **Audio Voiceover Synthesis:** English neural TTS voices (`en-US-ChristopherNeural`, `en-US-GuyNeural`, `en-US-JennyNeural`).
3. **Internal Helper Libraries:**
   * Safe Frame Renderer: `/opt/floworkos/skills/githubtoyoutube/scripts/safe_render_tools.py`
   * Viral SEO & Keyword Researcher: `/opt/floworkos/skills/githubtoyoutube/scripts/seo_researcher.py`
   * Procedural Kinematic Engine: `/opt/floworkos/skills/githubtoyoutube/scripts/stickman_engine_v2.py`
4. **Output Storage Vaults:**
   * System Vault: `/opt/floworkos/documents/videos/<theme_folder>/`
   * User Vault: `~/Documents/videos/<theme_folder>/`

## 3. Standard Operating Procedure

### The 4 Core Sovereign Directorial Laws
Every production generated by this skill MUST strictly adhere to these four foundational laws:

#### Law 1: 100% English Production Mandate (Wajib Bahasa Inggris)
* **Audio Voiceover:** Synthesized strictly with premium English neural TTS voices via `edge-tts`:
  * `en-US-ChristopherNeural` (Default authoritative male; deep, punchy, crisp cadence).
  * `en-US-GuyNeural` (Dynamic, enthusiastic, conversational male).
  * `en-US-JennyNeural` (Engaging, expressive, clear female).
  * *Prohibition:* Zero non-English voice models or mixed-language audio tracks.
* **On-Screen Visual Text:** 100% of on-screen elements must be in grammatically pristine, punchy English:
  * Hook Titles, Speech Bubbles, Exclamation Badges, Feature Cards, Kinetic Captions, Terminal Commands, Code snippets, and Dual-CTA text.
* **YouTube Metadata & SEO:** Video titles, YouTube descriptions, tags, and chapter markers must be exclusively in high-CTR English.

#### Law 2: Zero-Overflow Safe Frame Law (Tulisan Tidak Boleh Keluar Frame)
Vertical 9:16 Shorts (1080x1920) must strictly respect mobile viewport safe zones and never clip off-screen:
* **Horizontal Boundaries:** Usable Width $X \in [90, 990]$ (Minimum 90px margin on left and right edges; Maximum text width: 900px).
* **Vertical Boundaries:** Usable Height $Y \in [180, 1680]$ (Top 180px reserved to clear YouTube channel/search header; Bottom 240px reserved to clear player controls and icons).
* **Kinetic Captions Zone:** Subtitles strictly positioned at $Y \in [1460, 1540]$, centered horizontally at $X = 540$, with dynamic wrapping and box padding.
* **Algorithmic Extents Measurement:** Never render text blindly. Always measure width via `ctx.text_extents(text)` or `wrap_text_to_width()`. If text exceeds 900px, dynamically scale down font size: `scale = min(1.0, max_width / measured_width)`. Use `safe_render_tools.py` for guaranteed compliance.

#### Law 3: Mandatory GitHub Repository URL Prominence (URL GitHub Wajib Ada)
The exact target repository URL (`github.com/<owner>/<repo>`) MUST be explicitly visible to the viewer:
* **Top Header Pill:** Floating glassmorphism pill at $Y \approx 200\text{--}260$ displaying GitHub octocat icon and repository slug (`github.com/owner/repo`).
* **In-Scene Holographic UI:** Rendered in terminal mockups, browser URL bars, or holographic code viewports during architecture breakdown scenes.
* **Outro Dual-CTA Card ($t \ge 50\text{s}$):** Dedicated full-width card prominently highlighting the GitHub URL, an animated Star button with click SFX, and call to action to star the repository.

#### Law 4: Mandatory Post-Production Viral SEO & Traffic Research Protocol
Every generated video MUST be accompanied by comprehensive YouTube metadata, trending search query mining, and viral packaging before delivery:
* **30-Day Trend & Sentiment Mining:** Leverage `last30days` to extract trending developer discussions from GitHub, Reddit, and Hacker News over the last 30 days.
* **Empirical Search Traffic & Autocomplete Mining:** Query live YouTube (`ds=yt`) and Google search autocomplete APIs to extract real user traffic queries.
* **High-CTR Title Engineering & Linting:** Generate 5 scored title candidates targeting $<60$ characters for desktop and $<45$ characters for mobile feed safety.
* **High-Retention English YouTube Description:** 2-line curiosity hook above the fold, feature bullets, exact GitHub URL, timestamped chapters, search query cloud, and Flowork OS branding (`https://floworkos.com`).
* **Dual-Tier Viral Hashtag Matrix:** Broad High-Volume Tags (`#shorts #programming #developer #coding #github #ai #tech`) and Niche High-Intent Tags.
* **Automated Deliverables Execution:** Run `python3 /opt/floworkos/skills/githubtoyoutube/scripts/seo_researcher.py --repo "<owner>/<repo>" --output-dir "<target_dir>"` to generate `METADATA_SEO.json` and `SEO_PACKAGE.md`.

### Autonomous Production Pipeline (6 Phases)

1. **Phase 1: Repository Discovery & Research Dossier**
   * Inspect target GitHub repo: clone, inspect README, architecture, problem solved, star history, and core capabilities. Extract 3 core technical value propositions.
2. **Phase 2: Directorial Storyboard & Scripting (English)**
   * Structure: Hook (0-5s) $\to$ The Problem (5-15s) $\to$ The Solution (15-32s) $\to$ Deep Tech / Code (32-50s) $\to$ Outro & Star CTA (50-58s). Spoken word count: strictly 130–145 words.
3. **Phase 3: High-Energy English Audio & Cartoon SFX**
   * Voice synthesis: `edge-tts --voice en-US-ChristopherNeural --rate=+5% --text "<script>" --write-media voiceover.mp3 --write-subtitles subtitles.vtt`.
   * Cartoon procedural SFX: woosh (scene change), pop (speech bubbles), ding/chime (GitHub star CTA), buzzer (error/problem). Normalize via EBU R128 (`-14 LUFS`, `-1 dBTP`).
4. **Phase 4: Autonomous PyCairo Render & Visual Verification**
   * Vertical 1080x1920 @ 30fps. Import `safe_render_tools` for text measurement, bounding boxes, GitHub badges, and outro star cards.
   * Draw expressive rubber-hose stickman characters with fluid sine-wave limb articulation and animated eye blinks. Encode with `h264_nvenc` (or `libx264`) + `aac`.
   * Generate visual verification contact sheet: `ffmpeg -i output.mp4 -vf "select=not(mod(n\,180)),scale=270:480,tile=4x2" -frames:v 1 contact_sheet.png`.
5. **Phase 5: Post-Production Viral SEO, Trending Keyword & Traffic Research**
   * Execute `seo_researcher.py` to mine 30-day sentiment, live YouTube/Google search autocomplete queries, and lint high-CTR title variations. Generate `METADATA_SEO.json` and `SEO_PACKAGE.md`.
6. **Phase 6: Archival, Verification & Ledger Logging**
   * Save deliverables into `/opt/floworkos/documents/videos/<theme_folder>/` (mirrored to `~/Documents/videos/<theme_folder>/`):
     * `<VIDEO_NAME>.mp4` (Final vertical 9:16 video)
     * `<VIDEO_NAME>_contact_sheet.png` (8-frame visual inspection sheet)
     * `METADATA_SEO.json` (Structured YouTube metadata & search suggestions)
     * `SEO_PACKAGE.md` (Formatted YouTube title, description, tags & chapters)
   * Append production entry to `/opt/floworkos/skills/githubtoyoutube/PRODUCTION_LEDGER.jsonl`.

## 4. Verification
1. Verify 100% English audio, typography, and YouTube metadata.
2. Confirm zero text clipping off-screen using the 8-frame contact sheet (`contact_sheet.png`).
3. Validate that exact target GitHub URL is visible in both the header pill and outro CTA card.
4. Verify generation of `METADATA_SEO.json` and `SEO_PACKAGE.md` in output directory.
5. Verify ledger entry logged in `PRODUCTION_LEDGER.jsonl`.

## 5. Failure Modes
1. **NVENC Hardware Encoder Unavailable:** Fallback seamlessly to CPU software encoder (`-c:v libx264 -preset fast -crf 22`).
2. **Edge-TTS Rate Limiting:** Fallback to secondary neural voices (`en-US-GuyNeural` or `en-US-JennyNeural`) or cached audio clips.
3. **Text Overflow in Dynamic Repositories:** `safe_render_tools.py` automatically wraps lines and dynamically scales down font sizes to prevent viewport clipping.
