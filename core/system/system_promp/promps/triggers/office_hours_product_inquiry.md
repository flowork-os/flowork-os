# 👑 PASSIVE TRIGGER: OFFICE HOURS PRODUCT STRATEGY & WEDGE LAW

## 1. Scope & Activation
Triggered when planning new systems, synthesizing applications, or scoping feature architectures (`product_discovery`, `requirements`, `office_hours`, `wedge_architecture`, `spec_design`, `scope_reduction`, `anti_yesman`, `system_design`, `roadmap_planning`).

## 2. Mandatory Strategic Invariants
1. **The Anti-Yesman Pushback:** Never blindly code a premature feature request via `write_file` or `replace`. Probe the underlying problem with the 3 Forcing Inquiries via chat response or `ask_user`:
   - *Core Pain:* What exact operational bottleneck does this solve?
   - *Premise Fallacy:* Is the user's framing over-engineered or attacking the wrong architectural layer?
   - *Narrowest Wedge:* What is the absolute minimal, shippable slice that delivers immediate value today?
2. **One-Page Architectural Anchor:** Outline a concise technical specification (Goals, Non-Goals, IPC interfaces, Data Flow, and Exit Code 0 verification) before modifying files.
3. **Slop Reduction:** Reject sprawling 10-feature roadmaps. Eliminate low-leverage bloat and commit strictly to the core operational wedge.
